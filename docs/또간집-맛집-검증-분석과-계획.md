# 전문 맛집 발굴·검증(풍자의 또간집) — 분석, 구현 가능 범위, 구현 결과

작성: 2026-11-17. 표기: **[확인]** 직접 확인 · **[확실하지 않음]** 근거 약함 · **[미검증]** 실제 데이터로 아직 확인 못 함 · **[보고]** 임의 결정하지 않고 운영자에게 보고.

## 1. 현재 시스템 분석 [확인]
- 앱은 정적 웹앱(GitHub Pages). 서버가 없고, 하루 한 번 도는 GitHub Actions가 데이터를 모은다.
- 맛집은 저장하지 않는다. 장소 상세에서 구글 Places(앱 안, 실시간)로 5곳을 고르고, 구글이 안 되면 카카오로 대체한다.
- 앞서 만든 `tools/food-verify/`(유튜브 검증 1차 구현)가 이미 있다: 승인 채널, 제작지원 제외, 정보란 추출, 카카오 식별, 판정, `app/data/food-eligible.json`, 앱의 "승인 식당만" 스위치. 이번 작업은 이것을 **시리즈 채널(또간집)** 용으로 확장했다. 기존 네이버·구글·관광공사·공공데이터 연동 코드는 건드리지 않았다.

## 2. 구현 가능 / 어려운 항목 구분
| 요구 | 판단 | 이유(출처) |
|---|---|---|
| YouTube Data API로 채널 영상 수집(제목·ID·URL·채널·게시일·설명·조회수·좋아요) | **가능** | `channels.list`(핸들 조회)·`playlistItems.list`·`videos.list(snippet,statistics)`. 좋아요는 제공될 때만. 할당량: 1유닛/호출 수준, 하루 10,000유닛 (https://developers.google.com/youtube/data/determine_quota_cost) |
| 신규 영상만 주기 수집, 중복·반복 처리 방지 | **가능** | 업로드 목록에서 이미 받은 영상을 만나면 멈춤, 설명 해시가 같으면 재추출 안 함 |
| 영상 속 식당 전체 추출 + 역할 4종(언급/방문/최종 선정/1위) | **부분 가능 [미검증]** | 설명(정보란·타임스탬프 챕터)에서만 추출. 1위·최종 선정은 설명에 표시 글자가 있을 때만 올림. **또간집 설명이 실제로 어떤 형식인지 키가 없어 확인하지 못함** |
| 자막·음성으로 식당 추출 | **구현하지 않음** | 남의 영상 자막은 공식 API로 못 받는다(`captions.download`는 영상 수정 권한 필요: https://developers.google.com/youtube/data/reference/rest/v3/captions/download). 영상 다운로드·비공식 수집은 YouTube 정책이 금지(Scraping 항목). 채널 측 자막 제공 협의가 되면 추가 가능 |
| 구글 Places로 업체 매칭(상호·좌표·영업 상태·장소 ID) | **가능하나 키 필요** | 앱의 구글 키는 `github.io` 도메인 제한 키라 Actions에서 못 씀 → **서버용 키 `GOOGLE_PLACES_SERVER_KEY` 필요**. 없으면 카카오로 매칭(장소 ID는 못 남김) |
| 구글 업체 정보 저장 | **제한적** | 장소 ID만 영구 저장, 좌표는 30일, 상호·주소 원문·리뷰·평점은 저장 금지 (https://developers.google.com/maps/documentation/places/web-service/policies). 그래서 평점·영업 상태는 추천 순간에 실시간 확인 |
| 방문자 평점·리뷰 수 | **가능(구글만)** | 카카오·네이버 공식 API에는 평점이 없다(필드 확인) |
| 최근 리뷰의 평가 변화, 리뷰 작성 시점 집중도, 반복 문구, 이벤트성 리뷰 의심 | **제한적** | 구글 API는 리뷰를 **관련도 순 최대 5개**만 준다. 전체 시계열·분포는 알 수 없다. 5개 안에서 몰림·중복·이벤트 문구만 "위험 신호"로 분류하고, 표본이 3개 미만이면 `unknown`으로 둔다. 허위로 확정하지 않는다 |
| "장기간 방문자 평가가 양호" | **측정 불가** | 평점 이력을 저장할 수 없고 공식 API에 시계열이 없다. 이 우선순위 조건은 구현하지 못했다 |
| 네이버 평가 활용 | **불가** | 네이버 공식 검색 API는 평점·리뷰를 주지 않는다. 네이버 플레이스 리뷰는 공식 경로가 없어 사용하지 않았다 |

## 3. 또간집 채널 확인 [확인 / 일부 확실하지 않음]
- 또간집은 별도 채널이 아니라 **'스튜디오 수제' 채널(@STUDIO_SUZE)의 코너**다(검색 결과: https://www.youtube.com/@STUDIO_SUZE, 뉴스 기사들이 "유튜브 채널 '스튜디오 수제'의 '또간집'"으로 표기). 영상 제목에 한글 "또간집" 또는 영문 "Repeat Restaurant"가 쓰인다(검색 결과의 영상 제목). → 채널 전체가 아니라 **제목 필터(`또간집|Repeat Restaurant`)** 로 수집한다.
- **정확한 채널 ID(UC…)는 API 키가 없어 확인하지 못했다.** 추측해 넣지 않고, 첫 실행에서 `channels.list(forHandle=STUDIO_SUZE)`로 조회해 **채널 이름이 "스튜디오 수제"와 맞을 때만** 확정·저장한다.
- [확실하지 않음] 또간집 진행 방식: "인터뷰 대상자의 개인 맛집을 풍자가 방문해 그중 가장 맛있던 곳을 고른다"는 시청자 설명이 검색 결과에 있으나, 공식 설명은 확인하지 못했다.
- ⚠ 또간집은 2025년에 출연자 조작·뒷광고 의혹이 보도됐다(예: https://www.seoul.co.kr/news/entertainment/starinterN/2025/05/11/20250511500021 , https://news.nate.com/view/20250822n21464). 제작지원·유료 광고 **표시가 있는 영상은 제외**하지만, 표시 없이 이뤄진 협찬은 자동으로 걸러낼 수 없다. 이것이 방문자 평가 검증을 함께 두는 이유다.

## 4. 구현한 것 (코드 `tools/food-verify/`, 점검 `tools/check-food-verify.mjs`)
1. **채널 관리**(`data/channels.json`): 시리즈 채널 항목(핸들·기대 채널명·제목 필터·승인일). 채널을 추가하려면 항목만 더하면 된다(확장 구조). 초기엔 또간집 하나.
2. **영상 수집**(`series.mjs`): 핸들→채널 ID→업로드 목록→새 영상만→`videos.list`. 제목·ID·URL·채널명/ID·게시일·설명·조회수·좋아요 저장(`data/series-videos.json`). 25일마다 갱신, 삭제된 영상은 제거(YouTube 30일 규칙). 제작지원 영상은 표시만 남기고 설명은 저장하지 않는다.
3. **식당 추출·역할**(`lib.mjs extractSeries`): 타임스탬프 챕터와 📍 정보란 줄에서 식당 전체 추출. 역할 `winner`(1위·우승 표시) > `final`(최종 선정) > `visited`(소개) > `mentioned`(언급 구간). 근거 글자 없으면 올리지 않는다.
4. **업체 매칭**: 구글(서버 키 있을 때) → 카카오 순. 이름이 같고 (전화·도로명·동·영상이 소개한 시/군/구) 중 하나가 맞을 때만 자동 연결. 같은 이름 지점이 여럿이거나 근거가 약하면 **검수 큐**(`data/review-queue.json`)로 보내고 추천에 쓰지 않는다. 결과는 `data/extractions.json`, 업체는 `data/restaurants.json`.
5. **위험 신호 분류**(`reviewRisk`): `PERFECT_LOW_COUNT`·`TIME_BURST`·`DUPLICATE_TEXT`·`EVENT_WORDS` 중 2개 이상이면 `high`(추천 보류), 1개면 `watch`, 표본 부족이면 `unknown`. 구글 리뷰 분석은 `fetchReviews:true`(+서버 키)일 때만(비용 증가). 리뷰 본문은 저장하지 않는다.
6. **최종 선정**(`judge`, `contentScore`): 필수 조건을 모두 통과해야 하고(승인 채널에서 실제 소개된 이력 — 언급만으론 불가, 업체 정확 매칭, 폐업 아님, 위험 신호 high 아님) 그 뒤 **전문 콘텐츠 점수**로만 우선순위를 정한다: 최종 1위 5 > 최종 선정 3 > 소개 1 > 언급 0.3, 여러 회차 반복 소개 +1.5/회(최대 3회), 최근 24개월 +0.5. **가중치는 `weights.json`에서 관리자가 조정.** 평점은 점수에 넣지 않는다.
7. **앱 노출**(`nearby.js`): `food-eligible.json`이 켜져 있으면 승인 식당 중 구글 실시간 평점(보정 4.2 이상·리뷰 100 이상)·영업 중인 곳만, **전문 콘텐츠 점수 순 → 같으면 보정 평점 → 가까운 순**으로 최대 5곳. 부족해도 채우지 않고, 같은 식당은 한 번만. 화면은 기존 그대로(점수·배지 노출 없음). 꺼져 있으면 기존 동작.
8. **자동 실행**: 매일 수집(`collect.yml`)에 포함 + 또간집만 따로 도는 `food-verify.yml`(수동 실행, 매주 월요일). 키 설정 여부를 로그에 먼저 알려 준다(값은 출력하지 않음).

## 5. 데이터 저장 구조 (`tools/food-verify/data/`)
`channels.json` 채널 · `series-videos.json` 영상 · `extractions.json` 영상별 식당 추출·역할·매칭 · `restaurants.json` 업체(장소 ID·좌표·확인일·위험 신호) · `verdicts.json` 식당별 판정(상태·사유·점수·근거 영상) · `review-queue.json` 검수 대기 · `overrides.json` 관리자 승인/거절 · `state.json`. 수집·검증 일시가 각 레코드에 들어 있다(`fetchedAt`·`extractedAt`·`matchedAt`·`coordsAt`).

## 6. 검증 상태 — 완료라고 말할 수 있는 것과 없는 것
- **검증함(가짜 네트워크 시험, `check-food-verify.mjs`)**: 채널 이름 불일치 시 확정 안 함, 제목 필터, 협찬 영상 설명 미저장, 영상별 추출·역할·매칭 저장, 모호 지점 검수 큐, 점수·순서(1위 > 반복 소개), 중복 방지, 변경 없는 영상 재호출·재처리 안 함, 25일 갱신, 삭제 영상 제거, 구글 ID 저장·원문 미저장, 키 없으면 호출 안 함, 앱 정렬·5곳 상한·채우지 않음, 기존 동작 회귀(점검 8종·브라우저).
- **검증 못 함 [미검증]**: 실제 YouTube 응답, 또간집 설명의 실제 형식, 실제 구글/카카오 매칭 정확도, 평점 기준값의 적정성. 이 환경에는 API 키가 없다. **실제 또간집 데이터로 전체 과정을 돌려 본 적이 없으므로 "완료"가 아니다.**

## 7. 보고할 불확실한 점 [보고]
1. YouTube 약관의 "데이터 집계 금지" 항목이 여러 영상 데이터를 모은 후보 DB에 해당하는지 — 이번 시리즈 수집은 한 채널(단일 콘텐츠 소유자)이지만 판단은 운영자에게 있다.
2. 구글 서버 키 발급·비용(Places Text Search 호출 증가) 승인, 구글 데이터 저장 범위(좌표 30일 갱신)가 지켜지는지.
3. 카카오 장소 좌표·이름의 저장 조건(약관 미확인) — 구글 서버 키가 없으면 카카오 값을 저장하게 된다.
4. 또간집 설명 형식에 맞는 추출 규칙 보정 필요 — 첫 실행 뒤 `extractions.json`·`review-queue.json`을 보고 `lib.mjs` 규칙을 조정해야 할 수 있다.
5. 평점 기준값(4.2/100)은 추측값. "장기간 평가 양호"는 측정 수단이 없어 미구현.
6. 공개 저장소에 영상 설명·조회수 등 수집 데이터가 올라간다.

- **핵심 한계 [확인]**: **또간집 영상 설명(정보란)에는 식당 이름이 없다.** 정규 회차 31편 모두 타임스탬프 구간 0, 📍 표시 0이며, 지역 소개·메뉴 종류·해시태그·다음 회차 예고·수제샵 링크뿐이다("과연 풍자가 인정한 1등 맛집은 어디?"처럼 정답을 숨기는 문구). 설명 기반 추출은 이 채널에서 식당을 0곳 뽑는다(정상 동작).
- **댓글 경로도 쓸 수 없음 [확인]**: 공식 `commentThreads.list`로 31편의 댓글을 받아 보니 ① 제작진 댓글은 전부 수제샵 상품 판매 안내(상품명을 식당으로 오인한 항목이 나옴), ② 좋아요 상위 댓글은 시청자가 **추천한** 가게 목록("익산 30년차 추천 순위: 부광족발…")으로 방송에 나온 식당이 아닌데 실제 업체와 자동 연결까지 됐다. 잘못된 식당이 승인될 위험이 커서 **댓글 수집·추출을 제거**했다.
- 부가 관찰: 정규 회차 31편 중 25편 설명에 "🚀또간집 X (제품명) 여기서만 최저가" 제휴·판매 링크가 있다. 공식 광고 표시도 "제작지원" 문구도 아니어서 제외하지 않았다. 이 링크가 협찬성인지는 알 수 없으므로 운영자가 판단할 사항.

### 결론: 식당명은 공식 API로는 얻을 수 없다 → 선택지 [보고]
1. **수기 입력(구현 완료)**: 정규 회차 31개의 입력 틀(`tools/food-verify/data/manual-episodes.json`, 회차 번호·지역·게시일 채움)을 만들어 두었다. 관리자가 영상을 보고 `restaurants`에 `{name, role}`(winner/final/visited/mentioned)을 적으면, 자동 수집분과 똑같이 업체 매칭 → 모호하면 검수 → 필수 조건 → 콘텐츠 점수(최종 1위 우대, 회차 반복 가산) → 앱 5곳 노출을 거친다. 실제 업체와 매칭되지 않으면 추천되지 않는다.
2. **자막·음성 분석**: 남의 영상 자막은 공식 API로 받을 수 없다. 채널(스튜디오 수제)의 자막 제공 협의가 되면 같은 구조에 입력 경로만 추가하면 된다(별도 협의).
3. **뉴스·블로그로 후보 추정**: 네이버 검색 API(기존 연동)로 "또간집 {지역} 1위" 기사·블로그를 찾아 후보 이름을 **검수 큐로만** 보내는 방식을 검토할 수 있다. 제3자 글의 저장·이용 조건(네이버 약관)과 이름 추출 정확도를 확인하지 못해 구현하지 않았다.


## 9. 식당 이름 확보와 실제 매칭 결과 (2026-11-17)
- **식당명 출처 [확인]**: 또간집은 영상 설명에 식당명이 없으므로, 공개 자료인 나무위키 '또간집' 문서의 방영 목록 표(열 이름 "또갈집" = 방송에서 최종 선정한 식당)에서 회차별 최종 선정 식당을 읽어 입력했다. 회차 번호와 게시 날짜가 둘 다 맞는 영상만 입력했다(스핀오프 "간절한입"은 제외). 표에서 "보류"인 회차(EP.92·94·101·106·108·112)는 선정 식당이 없어 입력하지 않았다. 출처 URL은 각 식당의 `src` 필드에 있다. 나무위키는 CC BY-NC-SA 라이선스라 문서 글을 옮기지 않고 식당 이름이라는 사실만 기록했다.
- **입력 범위**: 최종 선정(winner) 식당 22곳(EP.85~111). 방문했지만 선정되지 않은 식당, 단순 언급 식당은 이 표에 없어 입력하지 못했다.
- **실제 업체 매칭 [확인, 카카오 로컬 API, GitHub Actions 실행]**: 22곳 모두 실제 업체와 연결(자동 연결). 처음엔 18곳이었고, 지점이 여럿인 곳은 공개 블로그에서 찾은 주소(도로명)로, 이름이 흔한 곳은 "도로명+상호" 2차 검색과 "상호+지점명" 이름 인정으로 해결했다. [확실하지 않음] 예돈돈까스(분당)는 지점이 여럿이라 블로그 2건이 적은 정자본점으로 연결했다.
- **판정 [확인]**: 22곳 모두 필수 조건(승인 채널의 최종 1위 소개 이력, 정확한 업체 매칭)을 통과해 `app/data/food-eligible.json` 에 들어갔다. 점수는 모두 5.5(최종 1위 5 + 최근 24개월 0.5).
- **미검증 [미검증]**: 구글 서버 키가 없어 구글 업체 ID 매칭·영업 상태·리뷰 위험 신호는 돌려 보지 못했다(앱이 추천하는 순간 구글로 영업 상태·평점을 실시간 확인하는 부분은 가짜 응답으로만 시험). 방송 후 폐업한 곳이 있을 수 있다(나무위키 각주에 폐업 업장 언급이 있음).
- **앱 반영 스위치(`appEnabled`)는 꺼 둠**: 지금 켜면 전국에서 승인 식당이 22곳뿐이라, 대부분의 여행지에서 맛집 목록이 비게 된다("5곳 미만이면 채우지 않는다" 규칙). 승인 식당이 더 쌓인 뒤 `config.json`에서 `appEnabled: true`로 바꾸면 된다.
