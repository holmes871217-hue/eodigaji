## 2. 구분
- **기능을 만드는 것**(선정 식당을 앞에 두고 표시): 가능. 이번에 만들어 두었다.
- **자료를 모으는 것**(목록 수집·저장): 서면 허가 필요. 허가 전에는 하지 않는다. 사용자가 직접 옮겨 적는 것도 약관상 "수동 프로세스"에 해당할 수 있어 권하지 않는다.

## 3. 이미 만들어 둔 장치 (허락 전에는 아무것도 달라지지 않음)
- 자료 파일 `app/data/blueribbon.json`: `license.status`(none/permitted), `source`, `verifiedAt`, `items[{n 이름, lat, lng, y 선정연도}]`.
- `license.status`가 **permitted일 때만** 앱이 자료를 읽는다. 그 전에는 비어 있어 기존 맛집 추천과 똑같다.
- permitted면: 같은 이름이면서 300m 안인 식당에 "블루리본 선정" **글자 표시**(로고·리본 그림은 쓰지 않음)를 붙이고, 맛집 순위에서 평점보다 앞에 둔다. 코스의 자동 맛집 선택에도 같은 순위가 쓰인다.
- 점검 `tools/check-blueribbon.mjs`(자동 실행에 연결): 허락 없이 자료가 들어 있으면 실패, 이름·거리 매칭과 우선순위 동작 확인.

## 4. 허가를 받으려면
`docs/블루리본-허가-문의-메일.md`의 초안을 br@bluer.co.kr로 보내고, 서면 답변을 받으면 그 내용(허용 범위·기간·표시 방법)에 맞춰 자료를 넣고 status를 permitted로 바꾼다. 허락 범위가 "표시만" 등으로 좁으면 그에 맞게 줄인다.
