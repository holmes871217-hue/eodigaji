# 유튜브 기반 맛집 검증 — 켜는 방법과 운영 (구현 완료, 기본은 꺼짐)

설계: `docs/유튜브-맛집-검증-설계.md`(개정 절 우선). 코드: `tools/food-verify/`, 점검: `tools/check-food-verify.mjs`.

## 지금 상태
- 코드·자동 실행·앱 연결까지 들어가 있고 **스위치가 모두 꺼져 있다.** 앱의 맛집 5곳은 기존 그대로다.
- 켜기 전에는 유튜브를 한 번도 호출하지 않는다(점검으로 확인).

## 켜는 순서
1. **API 키**: Google Cloud에서 YouTube Data API v3 키를 발급해 저장소 Settings → Secrets → Actions 에 `YOUTUBE_API_KEY` 로 등록한다(채팅에 붙여 넣지 말 것).
2. **수집 켜기**: `tools/food-verify/config.json` 의 `"collect": true`. 매일 새벽 수집 때 지역별 "{지역} 맛집" 검색(하루 90회, 213개 지역을 약 3일에 한 바퀴)을 한다.
3. **채널 승인**: 첫 실행 뒤 `tools/food-verify/data/suggestions.json` 에 검색에 나온 채널(채널명·나온 횟수)이 쌓인다. 믿을 만한 전문 맛집 채널만 `tools/food-verify/data/channels.json` 의 `approved` 에 `{ "id": "채널ID", "name": "이름", "approvedAt": "날짜" }` 로 넣는다. 승인된 채널의 영상만 맛집 후보가 된다.
4. **검수**: `data/review-queue.json`(식별이 모호한 후보)을 보고, 확실한 것은 `data/overrides.json` 에 `{ "카카오장소ID": "approve" }` 또는 `"reject"` 로 정한다.
5. **앱 반영**: 승인 식당이 충분히 쌓였으면 `config.json` 의 `"appEnabled": true`. 이때부터 앱의 맛집은 **승인된 식당만, 구글 실시간 평점 기준을 넘고 영업 중인 곳만** 나오고, 5곳 미만이면 그대로 보여 준다. 켜기 전에 지역 한 바퀴(약 3일)가 지나 대부분의 지역을 훑었는지 `food-eligible.json` 의 `count` 로 확인한다.

## 지켜지는 규칙 (자동 점검됨)
- 제작지원·협찬·광고 영상은 통째로 버린다(API의 유료 광고 표시 + 제목·설명의 문구). 저장하지도 않는다.
- 영상 제목·설명 전문은 저장하지 않는다. 영상 ID·채널 ID·게시일·추출한 식당 정보만 둔다.
- 영상 정보는 25일이 지나면 다시 받아 갱신하고, 없어졌으면 지운다. 30일 넘게 갱신하지 못한 정보는 판정에 쓰지 않는다.
- 같은 채널의 반복 소개는 독립 추천 1로만 센다(`minChannels` 기본 1).
- 평점은 저장하지 않고 추천 순간에 구글에서 받는다. 기준은 `RATING_RULE`(보정 평점 4.2 이상, 리뷰 100개 이상 — **추측값**, 운영하며 조정. `lib.mjs` 와 `app/js/core/nearby.js` 두 곳이 같아야 하며 점검이 확인한다).
- 한 영상에 12곳을 넘게 나열하면 나열형으로 보고 쓰지 않는다.

## 아직 확인이 필요한 것 (설계 문서 10장)
- YouTube 약관의 "데이터 집계 금지" 항목이 이 수집에 해당하는지 — 서면 확인 전에는 `collect` 를 켜는 판단을 운영자가 한다.
- 정보란 형식은 실제 영상으로 검증하지 못했다(API 키가 없어서 가짜 설명으로만 시험함). 켠 뒤 처음 며칠은 `review-queue.json`·`candidates.json` 을 보고 추출이 잘 되는지 확인해 `lib.mjs` 의 추출 규칙을 다듬어야 한다.

## 또간집(전문 시리즈 채널) 추가 안내
- 상세: `docs/또간집-맛집-검증-분석과-계획.md`. 채널은 `tools/food-verify/data/channels.json` 의 `ddagganjip` 항목(스튜디오 수제 @STUDIO_SUZE, 제목 필터 `또간집|Repeat Restaurant`)이다. 채널 ID 는 첫 실행에서 조회해 이름이 맞을 때만 채워진다.
- 필요한 키: `YOUTUBE_API_KEY`(필수), `KAKAO_REST_KEY`(이미 있음), `GOOGLE_PLACES_SERVER_KEY`(선택, 구글 업체 ID 매칭용 — 앱의 도메인 제한 키와 별개로 Places API 만 허용하는 서버용 키). 값은 저장소 Settings → Secrets → Actions 에만 넣는다.
- 실행: Actions → "또간집 맛집 검증 실행" → Run workflow. 로그 맨 앞에 키 설정 여부가 나온다. `config.json` 의 `collect` 를 true 로 해야 수집한다. `regionSearch` 는 지역 검색 수집(지금 꺼 둠).
- 가중치 조정: `tools/food-verify/weights.json`. 검수: `data/review-queue.json` 을 보고 `data/overrides.json` 에 `{ "업체키": "approve" | "reject" }`.
